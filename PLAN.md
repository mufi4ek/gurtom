# ҐУРТОМ / Together — план розробки v1.0

**Збірка ігор для компанії на телефон.** Українська (і англійська) локалізація, мінімалістичний
дизайн, повністю безкоштовно, монетизація лише рекламою. Розробник і правовласник — **mufidev**.

| | |
|---|---|
| Назва (ук) | **Ґуртом** |
| Назва (en) | **Together — Party Games** |
| Платформа | Android 7.0+ (API 24) → цільовий API 35 |
| Стек | Kotlin + Jetpack Compose + Room/SQLite |

## 1. Чому саме цей стек

**Kotlin + Jetpack Compose.** Вимога «Android-only, красиво і не як у 2000-му» закривається
Compose найкраще:

- Декларативний UI з вбудованою системою анімацій (`animateFloatAsState`, `AnimatedVisibility`,
  `AnimatedContent`, `Modifier.graphicsLayer`) — картка зі словом, що перевертається, таймер,
  що «дихає», і сплеш із лого робляться без сторонніх рушіїв.
- Material 3 + власна палітра = темна база з **неоновим акцентом, який користувач вибирає сам**.
- Один APK ~4–8 МБ (без Flutter-рантайму), швидкий холодний старт (<1.5 с).
- Google Mobile Ads SDK для Kotlin — першокласна підтримка, без міст і мостів.
- Compose Multiplatform лишає двері відчиненими: якщо колись знадобиться iOS —
  переписується тільки UI-шар, логіка ігор і словник переносяться як є.

**Чому не Flutter / RN:** для Android-only вони дають більший APK і зайвий шар;
AdMob-плагіни в RN вимагають нативних модулів, що ускладнює CI-збірку «одним воркфлоу».

**Чому SQLite, а не JSON у assets:** 43k записів з 30 полями. JSON = 23 МБ і парсинг на
кілька секунд; SQLite = **2.9 МБ у gzip**, миттєві вибірки з індексом
`WHERE difficulty=? AND age<=? AND actable=1 ORDER BY RANDOM() LIMIT 30`.
Це ключова продуктивнісна перевага.

## 2. Ігри (9 штук) і що саме вони вимагають від контенту

| # | Гра | Механіка | Джерело контенту | Офлайн | Лобі |
|---|-----|---------|------------------|:--:|:--:|
| 1 | **Аліас** | Поясни словами, не називаючи. Таймер 60 с, команди по черзі | `words` (усі pos, крім службових) | ✅ | ✅ |
| 2 | **Крокодил** | Покажи без слів і без звуків | `words WHERE actable=1` | ✅ | ✅ |
| 3 | **Хто я?** | Слово на лобі (телефон до чола), питання «так/ні» | `words WHERE animate=1 OR person=1 OR actable=1` | ✅ | ✅ |
| 4 | **Табу** | Поясни слово, не використовуючи 5 заборонених | `words WHERE taboo=1` (syn+hyp+hypo+mer ≥2) | ✅ | ✅ |
| 5 | **Капелюх** | 3 раунди: словами → показом → одним словом | спільний пул із Аліас/Крокодил | ✅ | ✅ |
| 6 | **Слова-ланцюжок** | Остання літера → перша літера | `words` (одинарні, noun/adj) | ✅ | ✅ |
| 7 | **Правда чи дія** | Питання або завдання | `party WHERE kind IN ('truth','dare')` | ✅ | ✅ |
| 8 | **Ніколи не** | «Я ніколи не…» + рахунок пальцями | `party WHERE kind='never'` | ✅ | ✅ |
| 9 | **Хто найбільше…** | Усі вказують на одного гравця | `party WHERE kind='likely'` + `emoji` | ✅ | ✅ |

Додатково як бонус-режими: **Фанти** (`party.kind='forfeit'`) — покарання за програш у Капелюсі,
і **Вгадай за емодзі** (`party.kind='emoji'`).

**Правила, які треба закодувати явно:**

- **Аліас.** Раунд = 60 с (налаштовується 30/45/60/90). Одне слово на екрані великим кепглем.
  Жести «вгору» = вгадав (+1), «вниз» = пропустив (−1 або 0 за налаштуванням), «струс» = пропуск.
  Слова не повторюються в межах гри. Заборонено показувати частини слова пальцями.
- **Крокодил.** Те саме, але слово можна тільки показувати. Таймер 60–90 с. Пул — лише `actable=1`
  (конкретні, візуальні слова), інакше гру неможливо виграти.
- **Хто я?.** Телефон тримають при лобі екраном до гравця. Гравець питає, компанія відповідає
  «так/ні». Ліміт — 20 питань або 2 хв. Важливо: для української показувати рід
  («Я — лікарка» / «Я — лікар»), тому в БД є поле `gender`.
- **Табу.** Слово + 5 заборонених (беруться з `syn`, `hyp`, `hypo`, `mer`, і обов'язково
  включають саме слово + його корінь). Є «детектор»: мікрофон не вмикаємо, але показуємо
  заборонені слова судді.
- **Капелюх.** Три раунди з тим самим набором слів: (1) пояснити словами, (2) показати,
  (3) пояснити одним словом. Слова, вгадані в раунді, повертаються в «капелюх» суперників.
- **Слова-ланцюжок.** Перевірка за останньою літерою; `ь`, `й`, `'` ігноруються
  (береться попередня значуща). Слова лише з БД, без повторів, таймер 15 с на хід.

2. **FrequencyWords / OpenSubtitles** (uk_50k) — ранги частотності для оцінки складності.
3. **Куруваний core-словник** (3 387 слів, 25 тем) — бо Вікісловник фізично **не містить**

4. **Ідіоми** — 140 курируваних фразеологізмів (окремий рядок на фразу, бо фрази

`topics` (до 3 ігрових тем), `difficulty`, `age`, `usage`, `actable`, `kids`, `taboo`,
`idiom`, `proper/person/place`, `unsuit`.

### 3.4 Складність: як вона рахувалася (важливо для довіри)

Наївний підхід («довша стаття = популярніше слово») давав **абсурд**: «офтальмолог»,
«геодезія» і «акмеїзм» потрапляли в легкий рівень, а звичайне «ганок» — у складний.
Причина: довжина статті вимірює якість документації слова, а не його вживаність.

Фінальна модель — **правила + позитивний доказ**:

1. **Легко (1)** тільки за наявності доказу: слово в курації `core` **або** має ранг
   частотності ≤ 3000 (≤6000/≤9000 із додатковими умовами на in-links і кількість значень),
   **і** належить до конкретної теми (`CONCRETE_TOPICS`), **і** це одинарне слово,
   **і** вік 6+. Субтитрова частотність завищує «філософія/місія/паніка», тому
   вимога конкретної теми обов'язкова.
2. **Складно (3)** примусово: 4+ слів, чутливий контент, 18+, службові слова
   (тут/там/багато/вам…), прапорці первинного значення `archaic | rare | dialect`,
   надто довгі фрази (>6 слів або >48 символів).
3. **Середньо (2)** примусово: 2+ слів, доменні прапорці (`technical, legal, medical,
   chemistry, it, military, religious, political`), власні назви, частотність ≤12000.
4. Решта розподіляється за рангом «вживаності» (частотність + in-links + кількість значень),
   щоб кожен рівень був наповнений.

**Принципова деталь:** прапорці беруться з **первинного значення**, а не з усієї статті.
Інакше «стіл» (має спеціальне геологічне значення «гора з плоскою вершиною») ставав
12+ і technical, а «яблуко» (застаріле «картопля») — 12+. Обидва тепер 6+, легко.

### 3.5 Вікові ворота

Користувач вибирає 6+ / 12+ / 18+ (можна кілька одразу; 16+ навмисне немає).
Без жодної верифікації віку — відповідальність декларована в Умовах використання,
а в застосунку є одноразовий дисклеймер при першому вмиканні 12+/18+.

- **18+ → лише 105 слів і ~40 карток.** Це свідоме рішення: продукт позиціонується як
  народна гра для компанії, тому відвертий контент майже відсутній, а нецензурна
  лексика **заблокована повністю** (`blocked=1`), навіть у 18+.
- **12+** — алкоголь/тютюн/зброя/смерть/флірт/лайт-лайка, плюс картки з підтекстом.
- **Чутливий контент** (`sens=1`, 189 записів, зокрема воєнні реалії) вилучено з
  дефолтного пулу — це не те, що хочеш пояснювати на вечірці.

## 4. UX: інформаційна архітектура та ключові потоки

### 4.1 Екрани

```
Splash (анімація лого mufidev/Ґуртом, ≤1.8 с, без реклами)
└─ Home (великі картки 9 ігор + «Швидка гра» + «Випадкова гра»)
   ├─ Налаштування гри (складність → вік → теми → кількість гравців/команд
   │                    → довжина раунду → мова)  ← 1 екран, 4 кроки, ≤20 с
   ├─ Гра (екран слова/картки + таймер + жест вгору/вниз)
   ├─ Раунд-результат (хто вгадав, скільки очок) → далі / реклама між іграми
   ├─ Підсумок гри (таблиця команд, рекорд, «зіграти ще»)
   ├─ Лобі (Створити / Приєднатися: QR, IP:порт, список пристроїв)
   ├─ Профілі та статистика (гравці, перемоги, улюблені теми, ачивки)
   └─ Налаштування (тема, акцентний колір, мова, реклама, звук/вібрація,
                    ліцензії, політика, умови, офлайн-дані)
```

### 4.2 «Швидкий старт» — головна вимога

Від тапу на іконку до першого слова на екрані — **≤3 тапи, ≤15 секунд**:

1. Тап по «Аліас» → 2. екран налаштувань із **збереженими минулими значеннями**
   і великою кнопкою «Грати» (а не обов'язковий майстер) → 3. слово.

Додатково: кнопка **«Швидка гра»** на Home — одразу раунд із дефолтами
(середньо, 6+, 60 с, 2 команди), **один тап**. І **«Продовжити»** — повторює
останню конфігурацію.

### 4.3 Жести й орієнтація

- Екран слова: **альбомна** орієнтація, слово на весь екран (72–96 sp),
  таймер-кільце зверху, лічильник очок.
-Swipe **вгору** = «вгадав» (зелений спалах + вібрація 20 мс + «+1»),
  swipe **вниз** = «пропустив» (червоний спалах), **струс** = пропуск.
- Для «Хто я?» — **портретна** орієнтація, телефон до чола, нахил назад = «вгадав».
- Картки Правда/Дія — перевертаються 3D-фліпом (`graphicsLayer { rotationY }`).
- Пауза: тап по таймеру або поворот екрана вниз. Під час паузи реклама не показується.

```
├─ data/
│  ├─ repository/       # WordRepository, PartyRepository, SettingsRepository,
│  │                    # StatsRepository, ProfileRepository
│  └─ engine/           # GameEngine: WordSelector (без повторів), RoundTimer,
│                       # ScoreKeeper, TeamRotator, RulesPolicy
├─ feature/
│  ├─ home/  ├─ setup/  ├─ splash/
│  ├─ alias/ ├─ crocodile/ ├─ whoami/ ├─ taboo/ ├─ hat/ ├─ wordchain/
│  ├─ truthdare/ ├─ never/ ├─ mostlikely/
│  ├─ lobby/            # LAN-хост і клієнт
│  ├─ profile/ ├─ stats/ ├─ settings/
│  └─ gameover/

└─ di/                  # Hilt modules
```

**Принципи:**
- Чиста логіка ігор (`engine`) не знає про Compose — її можна тестувати JVM-тестами.
- `WordRepository` — єдине місце, де формується пул слів. Запит завжди у вигляді
  `WordFilter(difficulty, ages:Set, topics:Set, pos:Set, actable, taboo, kids,
  excludeIds:Set, phraseMin, phraseMax)`.
- Жодного мережевого виклику для контенту: все в assets → `filesDir/gurtom.db`.
  Розпакування 2.9 МБ gzip займає <300 мс і робиться **в фоні на першому запуску**,
  зі сплеш-анімацією поверх (тому сплеш і потрібен — він приховує розпакування).
- Стан гри тримається у `ViewModel` + `SavedStateHandle`, щоб поворот екрана й
  вбивство процесу не скидали рахунок.

## 6. Локальне лобі (без сервера в хмарі)

Твоя ідея правильна: гра **хоститься на одному телефоні**, інші підключаються.
Найнадійніший сценарій для компанії — **хотспот**:

### 6.1 Сценарій А (основний): хост роздає Wi-Fi
1. Хост: «Створити лобі» → застосунок показує інструкцію «Увімкніть точку доступу»
   + кнопку-перехід у системні налаштування (`Settings.ACTION_WIRELESS_SETTINGS` /
   `ACTION_WIFI_TETHER_SETTINGS`).
2. Хост піднімає в застосунку **TCP-сервер** на `0.0.0.0:47820` (Java `ServerSocket`).
3. Хост показує **QR-код** із payload `gurtom://join?ip=192.168.43.1&port=47820&room=AB12&v=1`
   і рядок `IP:порт` великим текстом (для ручного вводу).
4. Гості підключаються до хотспоту, сканують QR (камера через CameraX) або вводять IP.
5. Клієнт відкриває сокет до хоста, шле `HELLO{name, avatarId, version}`,
   хост відповідає `WELCOME{playerId, roomState}`.

### 6.2 Сценарій Б: усі вже в одній Wi-Fi мережі
Те саме, але IP хоста береться з `WifiManager`/`NetworkInterface` і показується в QR.
Опційно — **mDNS/NSD** (`NsdManager`, сервіс `_gurtom._tcp.`) для автоматичного
пошуку хоста в списку «Знайдені ігри» без вводу IP. NSD на Android працює нестабільно
на деяких роутерах з ізоляцією клієнтів, тому це **доповнення**, а не заміна QR/IP.

### 6.3 Сценарій В: фолбек без мережі
«Передавай телефон» — класичний hot-seat: один пристрій по колу. Це **обов'язковий**
режим, бо він працює завжди (літак, село, розряджені телефони). Усі 9 ігор підтримують його.

### 6.4 Протокол (JSON over TCP, newline-delimited)

```
HELLO     {name, avatarId, appVersion}                 client → host
WELCOME   {playerId, room:{code, hostName, players[], state}}   host → client
LOBBY     {players[], settings{game,difficulty,ages,topics,roundSec,teams[]}}  host → all
READY     {playerId, ready:bool}                       client → host
START     {gameId, seed, settings, teams}              host → all   (однаковий seed!)
TURN      {playerId, cardId, deadlineEpochMs}          host → all
RESULT    {playerId, cardId, verdict:hit|miss|skip}    client → host
SCORE     {scores{teamId:points}, round, nextPlayerId}  host → all
END       {finalScores, winner, stats}                 host → all
PING/PONG {ts}                                         both
BYE       {playerId}                                   client → host
```

**Ключові рішення:**
- **Авторитет — хост.** Він володіє словником і генерує карти. Клієнт не отримує
  весь пул, лише свою карту — це і чесніше (не можна підглядіти в чужому телефоні),
  і легше (не треба синхронізувати БД між версіями).
- **Однаковий `seed`** у `START` дає детерміновану пословність карт: якщо хост
  перепід'єднається, гру можна відновити.
- **Таймер на хості**, клієнти отримують `deadlineEpochMs` і синхронізують відлік
  за `PING/PONG`-зсувом (NTP-подібно, ±50 мс достатньо для вечірки).
- **Таймаути:** 3 с на `PING`, реконнект 10 с, після чого хост передає хід далі.
- **Розрив зв'язку:** хост показує «Гравець X від'єднався» і пропонує
  «продовжити без нього» або «чекати 30 с».
- **Версійність:** `appVersion` у `HELLO`; при розбіжності — «Оновіть застосунок,
  щоб приєднатися» (щоб уникнути розсинхрону правил).
- **Дозволи:** тільки `INTERNET` + `ACCESS_NETWORK_STATE` + `ACCESS_WIFI_STATE`.
  Жодного `NEARBY_WIFI_DEVICES`, жодної геолокації → простіша форма Data Safety.

## 7. Дизайн-система

### 7.1 Тема
- **Темна база за замовчуванням** (`#0B0D10` фон, `#12151A` поверхні, `#1A1F26` картки).
- **Світла тема** на вибір (`#F7F8FA` фон, `#FFFFFF` поверхні).
- **Акцентний колір — користувацький**: 8 пресетів (неон-зелений `#39FF88`,
  ціан `#22E4FF`, маджента `#FF3CAC`, лайм `#C6FF3D`, бурштин `#FFB13D`,
  фіолет `#A855F7`, червоний `#FF4D5E`, білий `#EAF0F6`) + власний через ColorPicker.
- Акцент використовується **економно**: таймер, активна кнопка, підсвітка команди,
  прогрес. Решта — нейтральна сіра шкала. Це і є «мінімалізм»: не «мало елементів»,
  а «мало кольору».

### 7.2 Типографіка й масштаб
- Шрифт: системний (Roboto) + **опційно** власний (Inter/Manrope у `res/font`) —
  не тягне зайвого розміру, якщо лишити системний.
- Шкала: Display 72/96 (слово в грі), Headline 32, Title 22, Body 16, Label 13.
- Слово в грі масштабується під ширину (`autoSize` / `Text` з `onTextLayout`),
  щоб «електростанція» і «кіт» виглядали однаково впевнено.
- **Критично для української:** повний набір `іїєґ'` у шрифті й коректний перенос
  (`softWrap=false`, `maxLines=2`, `hyphens` вимкнено, бо українські дефіси
  у словах типу «хтось-небудь» не повинні ламатися).

### 7.3 Рух
- Сплеш: лого малюється штрихом (SVG `path` + `trimPath`-подібна анімація),
  потім літери «ҐУРТОМ» в'їжджають з `stagger` 60 мс, усе ≤1.8 с, далі — fade.
- Переходи між іграми: `AnimatedContent` зі `slideInHorizontally`.
- Картка Правда/Дія: 3D-фліп 320 мс, `FastOutSlowInEasing`.
- «Вгадав»: зелений спалах 120 мс + `scale 1.0→1.06→1.0` + haptic `Tick`.
- Таймер: кільце `drawArc`, останні 10 с — пульсація 1 Гц + червоний акцент.
- Увімкнути прапорець `Settings → Зменшити рух` (поважає `Settings.Global.TRANSITION_ANIMATION_SCALE`
  і дає вимкнути анімації вручну) — це вимога доступності.

### 7.4 Доступність
- Контраст тексту ≥ 4.5:1 у **обох** темах при будь-якому акценті
  (тому для акценту на тексті використовується `onAccent`, що рахується з фону).
- Усі жести мають **кнопковий еквівалент** («Вгадав» / «Пропустити»).
- `contentDescription` для всіх іконок, `semantics` для таймера
  (`liveRegion = LiveRegionMode.Polite`, але не частіше ніж раз на 5 с, щоб не спамити TalkBack).
- Мінімальна зона тапу 48 dp.
- Режим «великий текст» у налаштуваннях (×1.3).

## 8. Монетизація: точна політика показів

Твоя вимога: банери майже всюди, interstitial між іграми в Аліасі,
**жодної реклами під час гри**, і раз на ~15 хв у Крокодилі. Формалізуємо:

| Ситуація | Формат | Правило |
|---|---|---|
| Home, Налаштування, Профіль, Статистика, Лобі, Підсумок | **Banner** (320×50, adaptive) | Завжди, крім екрана гри |
| **Будь-який екран гри (слово/картка/таймер)** | **НІЧОГО** | Абсолютна заборона |
| Аліас: завершення **повної гри** (усі команди відіграли свої ходи) | Interstitial | Не частіше ніж раз на **2 гри** поспіль; після показу лічильник скидається |
| Крокодил | Interstitial | Не частіше ніж раз на **15 хвилин** ігрового часу |
| Інші 7 ігор | Interstitial | Не частіше ніж раз на **10 хвилин** і **не частіше 1 на 3 завершені гри** |
| Пропустити хід / додаткові 15 с / підказка синонімом | **Rewarded** | За бажанням гравця, без ліміту |
| Перший запуск, онбординг, сплеш, «Хто я?» з телефоном на чоло | НІЧОГО | Ніколи |

**Технічні запобіжники (обов'язково в коді):**
- `AdPolicy.canShowInterstitial(game, now)` — єдина функція рішення,
  з `SharedPreferences`-лічильниками: `lastShownAt`, `gamesSinceLast`, `minutesSinceLast`.
- **Захист від показу в невідповідний момент:** `AppOpenAd` не використовуємо взагалі
  (він часто вилітає поверх гри після розгортання). Замість нього — тільки interstitial,
  і він **preload'иться заздалегідь**, але `show()` викликається лише з екрана
  «Підсумок гри», у стані `RESUMED`, і ніколи коли `gameInProgress == true`.
- `RequestConfiguration` з `tagForUnderAgeOfConsent` — **не** встановлюємо
  (застосунок не дитячий), але при виборі 6+ показуємо лише family-friendly
  креативи через `maxAdContentRating = MaxAdContentRating.T` (Teen) замість MA.
- UMP GDPR/CCPA consent flow (`User Messaging Platform`) — обов'язково,
  без згоди показуємо лише non-personalized.

**Прогноз доходу (чесний):** для ніші «вечірки/ігри для компанії» в Україні
реалістично $0.5–2 на 1000 DAU/день при такій м'якій політиці. Тобто це про
продукт і портфоліо, а не про заробіток на старті. Якщо захочеш більше —
єдиний спосіб, що не ламає UX: додати IAP «Прибрати рекламу» (~79 грн),
це не суперечить «все безкоштовно», бо реклама лишається доступною всім.

## 9. Google Play: як пройти перевірку без проблем

### 9.1 Обліковий запис і тип
- Індивідуальний акаунт розробника ($25 одноразово). Для нових акаунтів Google вимагає
  **12–14 днів закритого тестування з ≥12 тестерами** перед production-доступом
  (політика 2023+, діє й досі) — заклади це в таймлайн.
- Або організаційний акаунт (потрібен D-U-N-S) — швидше довіри, але довше реєстрація.

### 9.2 IARC / віковий рейтинг
У Console → «Класифікація вмісту» відповідай так:
- Насильство: немає / мультяшне (0)
- Сексуальний контент: **«Іноді»**, бо є режим 18+ із фліртом → дасть **Teen/16+**
  за IARC. Якщо хочеш чисті **Everyone 10+**, вимкни 18+ деки у v1.0 і додай їх
  як окремий «дорослий» реліз пізніше.
- Лайка: «рідко» (лайт-лайка в 12+)
- Азартні ігри: немає (реальних ставок немає)
- Алкоголь/тютюн: «іноді» (картки 12+)

**Рекомендація:** для v1.0 ціль у **Teen (12+)**. Це дає ширше покриття і простішу
перевірку, а 18+ деки залишаються як опція з дисклеймером.

### 9.3 Data Safety
Застосунок не збирає персональних даних, якщо не вводити акаунти. Декларуємо:
- **Збирається:** ID пристрою для реклами (AdMob) — «Advertising ID»,
  призначення «Advertising», обмін з третіми сторонами — AdMob/Google.
- **Не збирається:** ім'я, email, телефон, геолокація, контакти, фото.
  Ім'я гравця в лобі зберігається **лише локально** і в мережу не йде
  (крім самого лобі в LAN) — так і пишемо.
- **Шифрування:** TLS для рекламних запитів; локальні дані — у `filesDir` (не шифруються
  окремо, це нормально і так декларують усі).
- **Видалення даних:** кнопка «Скинути статистику та профілі» в налаштуваннях +
  форма видалення даних за посиланням (вимога Play з 2024).

### 9.4 Атрибуція CC BY-SA 3.0 (обов'язково!)
Словник походить з uk.wiktionary, тому **має бути видиме зазначення авторства**:

1. Екран «Про застосунок → Ліцензії та джерела даних»:
   > Словник створено на основі матеріалів **Вікісловника (uk.wiktionary.org)**,
   > доступних на умовах ліцензії **Creative Commons Attribution-ShareAlike 3.0**.
   > Частотні дані — FrequencyWords (OpenSubtitles). Додаткова курація — mufidev.
2. Те саме в описі Play Store (розділ «Про застосунок», останній абзац).
3. Файл `assets/ATTRIBUTION.txt` у APK.
4. Оскільки CC BY-SA вимагає «share-alike» для **похідних творів**, а база даних
   є похідною, безпечна позиція: опублікувати `tools/` (скрипти збірки) і
   `dataset/gurtom.db.gz` у **публічному репозиторії під CC BY-SA 3.0**.
   Код застосунку при цьому лишається твоїм (Apache-2.0/MIT) — дані й код
   ліцензуються окремо, це стандартна практика.

### 9.5 Політика щодо UGC і реклами
- UGC (власні набори слів користувача) — лише **локально**, без публікації іншим.
  Це повністю знімає вимогу модерації. Якщо колись зробиш шаринг паків —
  знадобиться механізм скарг і модерації (політика Play про UGC).
- Реклама не може бути єдиною нагородою за ігровий прогрес (вимога Play) —
  тому rewarded дає **косметику/зручність** (додатковий час, підказка),
  а не «перемогу».

### 9.6 Технічні вимоги Play
- `targetSdk` = останній обов'язковий (на момент релізу — 35).
- **AAB** для production (`bundleRelease`), APK — тільки для тестів (твій сценарій).
- 64-bit (`arm64-v8a` + `armeabi-v7a`), `android:extractNativeLibs` не потрібен.
- Політика конфіденційності за публічним URL (обов'язково, навіть без збору даних).
- Декларація `AD_ID` permission (`com.google.android.gms.permission.AD_ID`) — потрібна для AdMob.
- Іконка adaptive (foreground/background/monochrome), скріншоти 6.7" і 5.5",
  feature graphic 1024×500.

## 10. CI/CD: збірка APK прямо з GitHub

Логіка твого сценарію: **coder.qwen.ai пушить код у GitHub → GitHub Actions збирає →
ти береш APK з Artifacts.** Воркфлоу готовий у `ci/android-build.yml`.

Що він робить:
- Тригер: `push` у `main`/`develop` + `workflow_dispatch` (ручний запуск) + PR.
- JDK 17, Gradle cache, `assembleDebug` → **APK у Artifacts** (твій основний шлях).
- `bundleRelease` → **AAB у Artifacts** (для Play Console).
- `signRelease`: якщо в репозиторій додані секрети `KEYSTORE_BASE64`,
  `KEY_ALIAS`, `KEY_PASSWORD`, `STORE_PASSWORD` — release-артефакт буде підписаний.
  Без них збирається unsigned (для Play це непридатно, для локальної перевірки — так).
- Lint + unit-тести (`testDebugUnitTest`) блокують збірку при помилках.
- Окремий job `dataset-check`: перевіряє, що `gurtom.db.gz` у assets валідний
  (розпаковується, містить очікувану кількість рядків).

**Що треба зробити тобі один раз:**
1. Створити репозиторій (напр. `mufidev/gurtom`).
2. Покласти `dataset/gurtom.db.gz` у `app/src/main/assets/`.
3. Додати 4 секрети для підпису (генерація ключа:
   `keytool -genkeypair -v -keystore gurtom.jks -keyalg RSA -keysize 2048 -validity 10000 -alias gurtom`,
   потім `base64 -w0 gurtom.jks` → у секрет `KEYSTORE_BASE64`).
4. Увімкнути Actions і взяти APK з вкладки Actions → Artifacts.

Час збірки: ~4–7 хв (перший запуск ~10 хв через кешування Gradle).

## 12. QA-план

**Юніт-тести (JVM, швидко, без емулятора):**
- `WordSelector`: не видає повторів у межах гри; при вичерпанні пулу — коректно
  перемішує заново; поважає `WordFilter`.
- `ScoreKeeper`: «вгадав» = +1, «пропустив» = −1/0, паритет, переможець.
- `AdPolicy`: не показує interstitial частіше за правила; **ніколи** під час гри.
- `WordChainValidator`: «хліб» → «балкон» (ігнорує `ь`), відхилює повтори й не-слова.
- `DifficultyGate`: слово з `age=12` не потрапляє у вибірку 6+.
- `LanProtocol`: серіалізація/десеріалізація всіх типів повідомлень.

**Інструментальні (Compose UI Test):**
- Home → Аліас → Налаштування → Гра: слово показується, swipe «вгору» додає очко.
- Поворот екрана не скидає рахунок.
- Таймер доходить до 0 і показує підсумок.

**Ручний чекліст перед релізом:**
- [ ] Холодний старт <2 с (перший запуск з розпакуванням <3 с)
- [ ] Жодної реклами на жодному ігровому екрані (перевірити всі 10)
- [ ] Реклама не з'являється після розгортання з фону під час гри
- [ ] APK працює в авіарежимі (усі ігри, крім лобі)
- [ ] Лобі: хост + 3 гості на хотспоті, 10 хв без падінь
- [ ] Реконнект гостя після вимкнення Wi-Fi
- [ ] TalkBack: можна зіграти повний раунд
- [ ] Світла й темна тема при всіх 8 акцентах — контраст читабельний
- [ ] Українські `іїєґ'` не ламаються ніде (зокрема в авто-розмірі слова)
- [ ] EN-локалізація: немає порожніх рядків, plurals коректні
- [ ] `adb shell dumpsys meminfo` — немає витоку після 20 ігор
- [ ] 60 fps на середньому пристрої (Redmi Note серії), перевірити `Profile GPU rendering`
- [ ] Розпакування БД не блокує UI-потік (перевірити на найдешевшому пристрої)

**Тестові пристрої:** один флагман (120 Гц), один бюджетник (Android 10, 2 ГБ RAM),
один планшет (перевірити ландшафт), один Samsung (найпоширеніший бренд в Україні).

## 13. Ризики та як їх закрито

## 14. Метрики (що міряти з дня 1)

Локально (без аналітики третіх сторін, щоб не ускладнювати Data Safety):
- `retention_D1 / D7`, сесій на користувача, середня тривалість сесії
- Ігри за типом (яка найпопулярніша) — вирішує, що розвивати
- Розподіл обраної складності й віку
- Конверсія «завантажив → зіграв першу гру» (ціль: >60%)
- Кількість завершених ігор на сесію (ціль: >2)
- Покази/кліки реклами через AdMob-дашборд

Якщо захочеш агреговану аналітику — Firebase Analytics **без** user_id і без
персональних параметрів; тоді Data Safety доповнюється одним рядком.
